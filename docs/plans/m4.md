# Milestone 4: per-city blocks that persist with the save, behind a forced backup

Owner's order (2026-10-06): save and pairing first, then realistic tunnels.

## Finished condition

Owner, in game: in an existing city, Ctrl+Shift+M asks "Enable Minecraft for this city?"; Yes writes a
backup save "<city> (before Minecraft) <date time>" that shows up in the load menu, then enters
Minecraft mode. Build some blocks, save the city, quit both games, start CS1 again, load the city:
the blocks are back. Load a different city: none of them are there. Load the backup: no blocks and
Minecraft not enabled. Quit without saving after building: the blocks are gone on the next load.

## Decisions

- **The city save is the authority for blocks** (protocol 1.5): the host keeps the city's edit set
  and writes it into the save as serializable mod data; Minecraft's world is a cache that the guest
  rebuilds on every `CITY_OPEN`. Loading an older save, Save As forks and quitting without saving
  then behave for blocks exactly as for the rest of the city, and no Minecraft world ever has to be
  deleted. Rejected: one Minecraft world per city (MC owns persistence): reverting to an older save
  would not revert blocks, forks would share one world, and world folders would pile up with
  nothing allowed to delete them.
- **Pairing** = the city carries our `SaveIdentity` record (existing, key unchanged). It is created
  only by the enable flow below, never silently. An unpaired city gets nothing written into it.
- **Forced backup before pairing**: the public `SavePanel.SaveGame(string)` (local save, the game's
  own routine, also used by the game's autosave) writes "<city> (before Minecraft) yyyy-MM-dd HHmm"
  under a name that does not exist yet (`" (2)"`, `" (3)"` appended otherwise; never an existing
  file: the game's routine replaces existing files and deletes its target on failure). Verified:
  the `.crp` exists, is at least 64 KiB, starts with the package magic `CRAP`, and its size is
  stable across two checks 1 s apart; time-out 120 s. Only then is the city paired. Failure: an
  error dialog, the city stays unpaired. The game's save routine also rewrites the launcher's
  `continue_game.json` to point at the backup; the mod restores that file's previous bytes after
  verification (if it existed before).
- **Self-test exception**: an unattended self-test in a city started from a map (never saved) pairs
  without the dialog and without a backup, and logs why. Every other path makes the backup.
- **Save barrier**: `OnSaveData` runs on the simulation thread; it sends `EDIT_SYNC` and waits up to
  2 s for the main thread to have applied the matching `EDIT_SYNC_ACK`, then serializes the edit set.
  Time-out: save what is there and log a warning.
- **Edit-set record** (key `MinecraftSkylines.CityEdits`): `u8 version = 1`, `u16 paletteCount`,
  palette strings (`u16` byte length + UTF-8), `u32 editCount`, edits sorted by (x, z, y) as
  `i32 x, i32 y, i32 z, u16 paletteIndex`, then `u32` CRC-32 (IEEE) of every preceding byte. No
  compression (Unity's Mono `GZipStream` needs a native helper that is not reliably present). An
  unreadable record loads as empty, is logged, and the raw bytes are kept and written back unchanged
  on save under the extra key `MinecraftSkylines.CityEdits.unreadable`, so a mod bug never silently destroys a city's blocks.
- **Minecraft side**: a new void world `skylines-city` replaces `skylines-dev` (which still holds
  untracked test blocks from M3; it is left untouched, and the docs tell the owner they may delete
  it). The guest persists the set of positions it may have changed (`<world>/mcskylines/touched.bin`,
  written atomically on every world save and on `CITY_CLOSE`), so a restart never leaves stray blocks.
- Not persisted in M4 (documented as limits): block-entity contents (chest items, sign text),
  entities (dropped items, item frames), the player's inventory and position. Creative mode stays.
- Uninstall: removing the mod leaves an inert data record in paired saves; CS1 ignores unknown mod
  data. Backups are ordinary saves.
